为什么用《仙剑奇侠传四》(3D RPG) 评测长程自主智能体？
不同于 2D 网格迷宫，agent-pal4 直接建立在 OpenPAL4 的原生 C++20 ChapterHost 与 AngelScript 2.2 (.csb) 字节码虚拟机之上，通过 JSON-Lines 协议向大模型智能体暴露真实的 3D 连续坐标空间、.nav 三角形导航网格、.evf 3D 触发器碰撞、多领队技能切换与回合制五灵战斗状态机，支持 Pure 纯净反作弊模式 与 Normal 诊断模式 双轨评测。
🏔️ 1. 3D 连续空间与 NavMesh 碰撞 真实执行 PlayerFreeMovement 相机相对方向运动、SceneCollision 球体-三角形碰撞与 3D .nav A* 导航网格寻路。
📜 2. 原版 CSB 虚拟机全指令闭环 完整实现 AngelScript 2.2 字节码（含 64-bit double 浮点指令 72..84）与 266 个原生系统调用，驱动全部 43 个原版 .csb 脚本模块。
🛡️ 3. Pure 模式消偏与反作弊 隐藏 quest_stage、mvar、script 等内部剧透字段，禁用 warp_scene/set_quest_stage/inspect_csb，迫使智能体依赖纯正空间观测与剧情推理。
⚔️ 4. 全四章主线与确定性重放 覆盖青鸾峰、石沉溪洞、寿阳柳府、女萝岩、淮南王陵、千佛塔、须臾幻境、鬼界、幻瞑界至卷云台终局决战，每份成绩均由 verify.mjs 逐步重放核验。

壹 · Pure 纯净模式 vs Normal 标准模式深度对比为什么 Pure 模式反而比 Normal 模式节省了 25% 的工具调用步数？

在 argon-20261105T032438 (Pure 模式) 中，gemini-4-argon-medium 仅用 36 步工具调用便完成了从青鸾峰到卷云台终局的全四章通关，比 Normal 模式（48 步）减少了 12 步 (-25.0%)：

🔒 观测脱敏 (Observation Sanitization) Pure 模式剥离了 quest_stage、trial_cleared、chapter1_cleared、diagnostics 以及 NPC/物体/事件的内部脚本名 script。
🚫 禁用跳关后门 (Debug Commands Blocked) 在 Pure 模式下调用 warp_scene、set_quest_stage、inspect_csb 或传入内部 func* 名称会被引擎直接拦截拒绝。
🧭 3D 传送门穿透与语义对齐 通过暴露 .evf 传送门 3D 几何中心与定向 interact(target) 自动寻路对齐，智能体不再需要在传送门边缘反复试探微调坐标。
⚔️ 零无效战斗指令 Pure 模式轨迹中 3 场 Boss 战（魁召、槐妖长老、玄霄与夙瑶）均为一击必杀且无多余的战后空挥调用。

叁 · OpenPAL4 无头引擎架构与确定性重放核验成绩不靠信任，靠 C++20 子进程逐步重放

为什么需要确定性重放核验 (bench/verify.mjs)？
大模型评测容易受到客户端日志篡改或环境不一致的影响。在 agent-pal4 中，每一局运行都会将完整的工具调用序列写入 episode.jsonl。运行 node bench/verify.mjs 时，核验器会启动一个全新的 agent-pal4-host C++20 子进程（固定伪随机种子 0xC0DEC0DE），按原顺序、原参数重新执行每一步工具调用，并逐步比对：
1. 逐步空间与状态快照比对 核对每一步调用后的 world、scene、领队 3D 坐标 leader.position、战斗胜场 combat.victories 与 game_cleared。
2. AngelScript 2.2 确定性虚拟机 CsbExecution 完整支持 32-bit 整型/浮点与 64-bit double 双精度指令集 (BC_ADDd..BC_F2D)，保证复杂机关（如须臾幻境 99 酒试炼）重放零偏差。
3. SHA-256 三重证据链绑定 verify.json 记录 result.json + episode.jsonl + client.jsonl 的联合 SHA-256 摘要；任何事后修改都会使 board.mjs 立即撤销「已核验 ✓」徽章。
4. 零 API 成本秒级复现 重放核验完全在本地 C++20 无头引擎中执行，无需调用任何外部 LLM API，4 局历史轨迹全部核验仅需不到 1 秒。
